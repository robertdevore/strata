# Custom provider endpoint policy

Custom providers are an explicit user trust decision. A configured provider receives the selected prompt/context and its own configured credential when the user invokes AI. Note contents and AI tools cannot select or replace the endpoint. Do not configure an endpoint you do not trust with that information.

Strata allows HTTPS endpoints on the internet, LAN and loopback. This deliberately supports local organizations' model servers; it is not a public URL-fetch proxy or an IP-based network firewall. URL credentials, query strings, fragments and protocols other than HTTP/HTTPS are rejected. Plain HTTP is restricted to exact loopback addresses: `127.0.0.1`, `[::1]`, or `localhost`, which is converted to `127.0.0.1` before connecting. For an IPv6-only local server, configure `[::1]` explicitly.

The URL parser canonicalizes numeric address aliases before validation. Known metadata names beginning `metadata.`, the name `metadata`, IPv4 0/8 and 169.254/16, IPv4 multicast/reserved high addresses, IPv6 unspecified, IPv6 link-local FE80/10 and IPv6 multicast FF00/8 are refused. IPv4-mapped IPv6 addresses receive the same IPv4 checks. FE80/10 includes FE90/FEA0/FEB0; checking only the literal text `fe80:` was insufficient. Address ranges are grounded in the [IANA IPv6 registry](https://www.iana.org/assignments/ipv6-address-space).

HTTPS hostnames use normal system DNS and TLS certificate/hostname validation. Strata does not pin resolved IP addresses or reject all private DNS answers, because HTTPS LAN servers are supported. A hostname resolving to an internal address is therefore not independently blocked. Do not disable Node TLS verification in the launch environment. The [Node TLS contract](https://nodejs.org/api/tls.html#tlscheckserveridentityhostname-cert) describes hostname verification. The literal-address guard does not claim to defeat a malicious configured HTTPS service or all DNS rebinding; the trust boundary is explicit endpoint configuration plus authenticated TLS, not arbitrary untrusted URL input.

Every request rejects redirects, shares a deadline across response headers/body, supports cancellation and limits response bytes to 4 MiB. Provider error bodies, request credentials and raw transport errors are not shown in user-facing failures. Transcription has its own bounded MIME/base64/decoded-size validation before requesting a provider. Normal verification uses synthetic responses and loopback fixtures, never paid live-provider calls.
